## 二、 P0 核心功能详细设计

### 1. 紧凑单行模式（Dense Mode）

#### 1.1 需求背景
目前每张卡片（Card）高约 `80~120px`，单屏仅能展示 6~8 条。在开盘期间，活跃用户密集发评、多条短帖同时涌入时，容易错过重要信息，需要频繁滚动翻找。

#### 1.2 交互与视觉设计
1. **视图切换入口**：
   - 顶栏操作区增加「紧凑视图 / 卡片视图」切换按钮（图标采用列表行形态 `≡`）。
   - 用户选择持久化到 `localStorage: diting.dense`（布尔值）。
2. **紧凑单行样式规格**：
   - 每行高度压减至 **28px ~ 32px**。
   - 采用单行流式排版：
     `[4px 左侧色条] [时间 HH:MM] [博主名称] [类型 Pill] [所属吧名] 正文摘要（溢出文本截断省略）`
   - 维持既有配色规范：左侧色条与用户名保持用户色，类型 Pill 保持类型色。
3. **详情展开机制**：
   - **单击单行**：向下平滑展开完整正文、上下文卡片（如 `[评论《xx》]`）、发布完整时间及「打开原帖 ↗」链接。
   - **鼠标悬停（Hover）**：浮动微型 Tooltip 展示前 100 字摘要，免点击即可快速扫读。

## 二、 正文全局搜索与全库历史检索

#### 2.1 需求背景
盘中某板块或个股异动（例如某光模块个股暴涨），用户需要快速核实：“我关注的博主最近几天有没有提及该标的或相关逻辑？” 目前界面没有任何搜索能力，只能在渲染出的 DOM 上按 `Ctrl + F`，无法检索更早入库的历史消息。

#### 2.2 两级检索机制设计
```
┌──────────────────────────────────────────────────────────────────┐
│  🔍 搜索关键词、股票或博主... (快捷键 /)             [ Esc 清空 ] │
└──────────────────────────────────────────────────────────────────┘
```

1. **第一级：瞬时前端过滤（Instant Filter）**
   - 搜索框常驻顶栏，按快捷键 `/` 直接聚焦，按 `Esc` 退出。
   - 输入关键字后，防抖 200ms 过滤当前已加载的所有条目，匹配的文本高亮（`<mark>`），不匹配的条目淡化或隐藏。
2. **第二级：全库历史回溯（Database Deep Search）**
   - 列表顶部/底部显示：“已在当前加载中找到 N 条匹配。点击【检索数据库全部历史】”。
   - 用户按下回车或点击该按钮，向后端请求历史搜索接口，并在独立视图或当前列表中呈现全库匹配结果。

#### 2.3 后端 API 契约
- **请求方式**：`GET /api/search?q={keyword}&limit=100`
- **处理逻辑**：
  - 检索 `messages.db`：
    ```sql
    SELECT key, name, kind, icon, time, bar, content, link 
    FROM messages 
    WHERE content LIKE ? OR bar LIKE ? OR name LIKE ?
    ORDER BY time DESC LIMIT ?
    ```
  - 独立短连接，用完即关，不与写线程争抢连接。
- **响应格式**：
  ```json
  {
    "ok": true,
    "items": [...],
    "count": 12
  }
  ```

## 三、 Web 端在线增删用户与参数管理

#### 3.1 需求背景
目前监控目标的新增、删除、备注修改均需手工编辑 `config.json`，且需重启或触发特定逻辑，存在格式改错（如缺少逗号）导致程序异常退出的风险。

#### 3.2 界面交互设计
在现有的右侧设置抽屉（`SettingsDrawer`）进行扩展：
1. **「+ 添加监控用户」板块**：
   - 输入框 1：**用户 UID**（必填，只允许数字）。
   - 输入框 2：**备注名**（选填，若为空则自动带出东财昵称）。
   - **「测试/获取昵称」按钮**：点击向后端发送探测请求，后端请求东财主页验证该 UID 是否真实存在，并回显真实用户名供确认。
   - 点击 **「确定添加」** 即刻入库生效。
2. **现有用户行操作扩充**：
   - 增加「🗑 删除」按钮（带二次确认提示框）。
   - 支持直接点击备注名进行就地编辑（Inline Edit）。
3. **全局运行参数配置**：
   - 抽屉底部增加输入区：
     - **股吧轮询间隔**（默认 30~60 秒）
     - **查追加检查间隔**（默认 300 秒）
   - 保存时一并写回 `config.json` 顶层配置并实时热更新。

#### 3.3 后端 API 契约
- `GET /api/probe_user?uid={uid}`
  - 探测 UID 真实性，返回 `{ "ok": true, "name": "某某大V" }`。
- `POST /api/users/manage`
  - 载荷示例：
    ```json
    {
      "action": "add",
      "user": { "uid": "123456", "name": "大佬A", "color": "#ED5126" },
      "config": { "poll_interval_seconds": 30 }
    }
    ```
  - 安全落地：先写 `.tmp` 临时文件后 `os.replace`，广播 `config` 事件通知所有前端。

## 四、 P1 级功能详细设计

### 1. 盯盘清脆声音提醒（Audio Ding）

- **技术选型**：
  - **绝不引入外部 `.mp3`/`.wav` 资源**（保证离线与零体积）。
  - 直接利用浏览器标准的 **Web Audio API**，仅用 ~15 行纯原生 JS 代码实时合成正弦波（Sine Wave）音效：
    - 基频从 880Hz（A5 音）微滑到 1760Hz（A6 音），在 0.25 秒内指数级衰减，音质清脆空灵不刺耳。
- **触发逻辑与防扰控制**：
  - 顶栏增加声音开关（小喇叭按钮 `🔊 / 🔇`）。
  - **防干扰判定**：仅当 `document.visibilityState !== "visible"`（即页面处于非激活后台或屏幕被遮挡）且有新动态到达时触发。如果用户正看着页面，则静默更新，不打扰思维。

---

### 2. “上次看到这里”未读断点分界线

- **技术选型**：
  - 前端监听 `visibilitychange` 事件。
  - 当页面在非可见状态超过阈值（如 3 分钟），在本地状态记录切走瞬间列表的最新一条动态的 `key`（`lastSeenKey`）。
  - 当新动态追加进来且用户重新切回页面后，在 `lastSeenKey` 的下一条条目上方渲染一条醒目的横向指示线：
    ```html
    <div class="unread-divider">
      <span class="line"></span>
      <span class="badge">🔴 上次看到这里（10:35）</span>
      <span class="line"></span>
      <button class="clear-btn">✕</button>
    </div>
    ```
  - 用户滚过该区域或点击右侧 `✕` 时，分界线平滑淡出。

## 六、 实施工艺与安全隔离路线（Git Worktree）

为严格保证**不干扰当前正在盯盘使用的运行实例**，后续开发必须遵循以下工艺：

```
主目录 (e:\personal\projects\guba-monitor)
  │── 当前运行中: 端口 17777 (生产盯盘，代码完全不动)
  │
  └── 执行命令: git worktree add ../guba-monitor-dev -b feature/v2-enhancements
        │
        └── 独立开发目录 (e:\personal\projects\guba-monitor-dev)
              ├── 开发启动: python server.py --mock --port 18888
              ├── 独立进行前后端代码编写与测试
              └── 验收通过后，merge 回 main 并清理 worktree
```

### 实施分步计划：
- **第一步**：建立独立工作树与分支，启动独立端口的 `--mock` 模式。
- **第二步**：实施 P0-1 **紧凑单行模式**（纯 CSS + `app.js` 扩展）。
- **第三步**：实施 P0-2 **全局搜索功能**（前端过滤 + 后端 `/api/search` 接口）。
- **第四步**：实施 P0-3 **Web 端用户与参数管理**（前端抽屉表单 + 后端 `/api/users/manage`）。
- **第五步**：实施 P1-1 **声音提示** 与 P1-2 **未读断点线**。
- **第六步**：全面离线验证，合并分支，无缝升级。
