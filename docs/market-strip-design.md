# 大盘条（Market Strip）设计

> 状态：**已实现**（`market.py` + `server.py` 注入 + `web/app.js` 的 `MarketStrip`）。视觉稿见 [market-strip-mock.html](market-strip-mock.html)（用浏览器直接打开，离线可用，含浅/深色切换和各状态）。
> 实现时数据源从东财换成了腾讯，见 §1 的说明；其余按本文。
> 目标：在网页版最上方加一条 30px 的长条，常驻显示 A 股三大指数、两市成交额，以及相对昨日同时段的放量/缩量。

## 1. 数据源（腾讯行情，2026-09-18 验证）

全部是公开接口，不用 Cookie、不用 Referer，只带 `User-Agent`。与股吧抓取一样属于非官方接口，随时可能变。

| 用途 | 接口 | 关键字段 |
|---|---|---|
| 实时行情（批量） | `https://qt.gtimg.cn/q=s_sh000001,s_sz399001,s_sz399006,s_sh000300` | GBK 文本，一行一个 `v_s_xxx="…"`，`~` 分隔：1 名称、2 代码、3 现价、4 涨跌额、5 涨跌幅 %、6 成交量（手）、7 成交额（万元） |
| 最近 5 个交易日的分时 | `https://ifzq.gtimg.cn/appstock/app/day/query?code=sh000001` | `data.sh000001.data[]` 每天 `{date: "yyyymmdd", data: ["HHMM 价格 累计成交量(手) 累计成交额(元)", …]}`，242 行/天。**累计额直接可用**，「昨日同时段」就是昨天同一分钟那行 |

代码前缀：`sh` 沪市、`sz` 深市。上证 `sh000001`、深成 `sz399001`、创业板 `sz399006`、沪深300 `sh000300`。

实时性：`qt.gtimg.cn` 盘中返回当前快照（与东财网页同步，延迟秒级），非交易时段返回收盘值。分时最后一行（1500）的累计额与快照的成交额完全一致（已核对：上证 9942 亿、深证 1.0829 万亿）。

**口径陷阱**：腾讯/东财在 `399001` 下报的成交额是**深市全市场**合计（与东财首页「两市成交」一致），而新浪的 `sz399001` 只是深证成指成分股合计（今天 5658 亿 vs 1.0829 万亿），不能混用。腾讯 5 分钟 K 线（`kline/mkline?param=…,m5`）只给成交量不给成交额，所以不用它。

**为什么不用东财**：设计阶段先验证的是东财 `push2.eastmoney.com/api/qt/ulist.np/get`（实时）和 `push2his.eastmoney.com/api/qt/stock/kline/get?klt=5`（5 分钟 K，且带成交额），数字与腾讯一致；但实现时本机 Python / curl 对这两台主机的请求开始被 TLS 层直接断连（`RemoteDisconnected`、curl `000`、schannel「server closed abruptly」），12 次里 0 次成功，`--resolve` 到真实 IP 也一样，而**同一台机器的浏览器打开东财行情页、对同样的 push2 接口全是 200**。像是 push2 的 WAF 按客户端 TLS 指纹 + 频率拦非浏览器请求，不是封 IP。腾讯接口 12/12 成功，故切换；东财 URL 记在这里备用。同花顺 `d.10jqka.com.cn` 能通但大部分接口要 `hexin-v` 签名，腾讯够用就没碰。

## 2. 「放量 / 缩量」口径

- **成交额** = 上证指数 + 深证成指 的成交额（沪市 + 深市，显示时换算成亿 / 万亿）。不含北交所，跟东财首页「两市成交」口径一致。
- **放量/缩量按成交额比**，跟东财的「较昨日 ±xxx 亿」同口径（一开始按成交量比过，数字和东财对不上：同一天成交量 +7% 而成交额 +14%，因为价格涨了、大票活跃）。条上同时显示差额（`+2540亿`）和百分比。
- **昨日同时段** = 昨天分时里同一分钟（`HHMM`）的累计成交额，两市相加；午休按 1130、收盘后按 1500。
- **比值** `ratio = 今日累计额 / 昨日同时段累计额 − 1`，`diff = 今日累计额 − 昨日同时段累计额`：
  - `≥ +10%` → 标「▲ 放量」（琥珀色 pill）
  - `≤ −10%` → 标「▼ 缩量」（灰色描边 pill）
  - 中间 → 不打标签，只显示带符号的百分比
- 阈值 10% 先写死，做完看一周实际数据再决定要不要做成配置。
- **集合竞价（9:15–9:25）** 不算比值（成交额还太小），显示「开盘后开始比较成交量」。
- **收盘后 / 非交易日** 比值改为「全天 vs 昨日全天」，文案跟着变。

## 3. 交易时段判断（后端）

只按本机时间 + 星期判断，不查节假日表：

| 阶段 | 时间 | 显示 |
|---|---|---|
| `pre` | 9:15–9:30 | 集合竞价（黄点） |
| `open` | 9:30–11:30、13:00–15:00 | 盘中（绿点） |
| `lunch` | 11:30–13:00 | 午间休市（灰点） |
| `closed` | 其它工作日时间 | 已收盘（灰点） |
| `holiday` | 周六日 | 休市（灰点） |

法定节假日落在工作日时会被误判成「已收盘」，靠分时兜底：分时的 5 天里没有今天，且已过 9:35（盘中）或 15:00（收盘后），就按 `holiday` 处理，`trade_date` 改成分时里最后一个交易日。9:35 之前不下结论。这样够用，不引入节假日表。

## 4. 刷新节奏

由**后端**控制，前端只被动收：

- `open` / `pre`：每 **10 秒**拉一次实时快照；每 **60 秒**拉一次两市分时（算昨日同时段、判交易日）。
- `lunch`：每 60 秒拉一次（数据不动，主要是为了 13:00 能及时切回 `open`）。
- `closed` / `holiday`：每 30 分钟兜底拉一次（跨天、判节假日）；工作日 8:45 之后改成每分钟，保证 9:15 准时切到 `pre`。
- 失败退避：连续失败按 10s → 30s → 60s → 5min 拉长，成功后回到正常间隔。失败时保留上次数据并淡化显示，条上给一句错误文案（不弹窗、不影响动态列表）。

网页端不再单独轮询：后端拉到新数据就通过现有 SSE 通道广播一个新事件 `("market", {...})`，与 `status` 事件同级；SSE 连上时先补发一条当前值，`/api/snapshot` 里也带一份供首屏和重连合并。这样多个标签页 / 平板副屏共用一份请求，不会放大对行情接口的请求量。

实现落点：`market.py` 的 `MarketFeed`（独立 daemon 线程，`server.py` 的 `main()` 创建并 `start()`，`broadcast` 回调直接用 `core._broadcast`），与股吧监控的启停完全无关；`MockMarketFeed` 覆写两个 `_fetch_*` 方法用假数据，阶段仍按真实时钟判断，所以 `--mock` 在盘中/盘后看到的条是不一样的。

## 5. 接口契约

新增 SSE 事件 / snapshot 字段 `market`，形状：

```json
{
  "phase": "open",                      // pre | open | lunch | closed | holiday
  "at": "14:07:30",                     // 后端本次成功拉取的时间
  "trade_date": "2026-09-18",           // 本条数据所属交易日
  "idx": [
    {"code": "000001", "nm": "上证",   "px": 3911.87,  "chg": 0.94},
    {"code": "399001", "nm": "深成",   "px": 13640.87, "chg": 1.72},
    {"code": "399006", "nm": "创业板", "px": 3372.68,  "chg": 2.25},
    {"code": "000300", "nm": "沪深300","px": 4507.39,  "chg": 1.06}
  ],
  "amt": 1462000000000,                 // 两市成交额，元；集合竞价阶段也给
  "vol": {                              // 算不出来时为 null（集合竞价 / 昨日 K 线没拉到）
    "ratio": 0.124,                     // 今日成交额 / 昨日同时段成交额 − 1
    "diff": 254000000000,               // 今日成交额 − 昨日同时段成交额，元；条上显示成「+2540亿」
    "tag": "more",                      // more | less | flat
    "vs": "vs 昨日同时段"               // 后端直接给文案，前端不做时段判断
  },
  "err": null                           // 失败时是一句中文，前端原样显示
}
```

`nm` 由后端给短名（接口返回的是「上证指数 / 深证成指 / 创业板指 / 沪深300」，条上放不下）。

## 6. 前端

- 位置：`.app` 网格新增第一行 `auto`，条本身 `grid-column: 1 / -1`，在顶栏之上；收起后该行高 0，布局回到现状。
- 折叠：右侧 ✕ 收起，状态存 `localStorage diting.market`（布尔，经 `store` 小工具）；收起后顶栏多一个图表图标按钮（宽屏）/「⋯」菜单里的「显示大盘」（窄屏）恢复。
- 响应式按信息价值逐级减（对应现有断点，改成 `@media`）：
  - `≤1150px`：去掉沪深300、「vs 昨日同时段」文字、百分比、迷你双柱
  - `≤940px`：再去掉刷新时间、收紧间距
  - `≤800px`：再去掉阶段文字、「两市」标签
  - `≤720px`：再去掉点位，只留涨跌幅（每档阈值 ≈ 上一档内容实际需要的宽度，避免刚跨断点就留一大截空白）
  - `≤480px`：再去掉成交额和 ✕
- 颜色：指数红涨绿跌沿用 `--stock-red` / `--ok`；放量 pill 用 `--warn` 系（需在 `:root` 新增 `--warn-soft`），缩量 pill 灰色描边——放/缩量本身不分好坏，刻意不用红绿。
- 收盘 / 非交易日 / 接口失败三种状态给 `.stale`，数字 `opacity: .55`。
- 迷你双柱：今日 vs 昨日同时段，长的那根撑满 44px，另一根按比例；今日那根用 `--accent`。

## 7. 不做的事

- 不做个股 / 板块 / 涨跌家数 / 北向资金——这是股吧动态监控工具，大盘条只是抬头看一眼的背景信息，不往行情软件方向走。
- 不做前端直连行情接口（违反「浏览器只请求 127.0.0.1」的约束，平板副屏也用不了）。
- 不做节假日表。
- 不做 tkinter 版。
